# A quantum-resilient Ethereum leg

QoreChain verifies ML-DSA-87 natively (`pqcVerify`, precompile `0x0a01`), so every dollar that comes *home* to
QoreChain was always attested post-quantum. The other direction was the weak point: Ethereum has no post-quantum
precompile, so money *leaving* QoreChain was minted on Ethereum on the strength of one secp256k1 signature. A
quantum computer that recovered that key could have minted on Ethereum at will.

This page is the study of every way to close that gap, what was built, what was measured on Sepolia with real
transactions, and what is left for later.

## What runs today

The Ethereum leg is a `HybridAttestedMessenger`: a CCTP V2 message from QoreChain is executed only with **both** the
attester's secp256k1 signature **and** a post-quantum proof over the same digest, the way QoreChain itself signs every
transaction twice. It has no owner: the remote side is fixed at deployment, and the only way to change the attesters
is a rotation attested by the current ones, both signatures. The post-quantum check is pluggable, and two are deployed
side by side:

| | ML-DSA-44 (FIPS 204) | Merkle WOTS+ (XMSS construction) |
|---|---|---|
| Contract | `MlDsa44AttestationVerifier` on ZKNox's NIST verifier | `MerkleWotsAttestationVerifier` (ours) |
| Standard | NIST FIPS 204, level 2 | hash-based; XMSS is RFC 8391 / NIST SP 800-208, here on keccak256 |
| Security assumption | Module-LWE / SIS lattices | keccak256 only (Grover: ~128-bit) |
| Signer | `mldsa44.sign` from QoreChain's own PQC kit (`@qorechain/pqc`) | `keeper/src/pqeth.ts` |
| State | stateless | stateful: one leaf per attestation, enforced on chain |
| Capacity | unlimited | 1,024 attestations per tree (height 10), then a rotation |
| Proof size | 2,420 bytes | about 2.6 kB ABI-encoded (67 chains + 10-node path) |
| Verify, Foundry | **8,324,201 gas** | **279,504 gas** |
| Whole relay on Sepolia (mint + subscription included) | **8,709,589 / 8,856,702 gas** | **663,048 gas** |
| One-time setup | expanded key in SSTORE2 (~4.6M gas, once) | the Merkle root (32 bytes) |

## Every option considered

| Option | Post-quantum end to end | Ethereum cost | Status |
|---|---|---|---|
| **A. ML-DSA-44 in Solidity** (ZKNox ETHDILITHIUM, NIST variant) | yes (FIPS 204, level 2) | ~8.3M gas per message | **built, live, default** |
| **B. Merkle WOTS+ in Solidity** (XMSS construction on keccak256) | yes (hash-based) | ~0.28M gas per message | **built, live, one rotation away** |
| C. ML-DSA-87 in Solidity, the same key as QoreChain | yes (level 5) | about 3x option A: above the 16.7M per-transaction cap with today's public verifier | **not feasible today**: see below |
| D. ETHDilithium (ZKNox's Keccak variant of ML-DSA-44) | yes, but not FIPS 204 (SHAKE replaced by Keccak) | ~4.9M gas (ZKNox) | not built: a non-standard hash to save 40% was not worth leaving FIPS 204 |
| E. Falcon / FN-DSA (ZKNox ETHFALCON) | yes (draft FIPS 206) | cheaper than ML-DSA on the EVM, per ZKNox (not measured here) | not built: floating-point signer, no QoreChain kit support |
| F. SLH-DSA (SPHINCS+, FIPS 205), stateless hash-based | yes | heavier than WOTS+ (many more hashes per signature) | not built: B gives the same assumption at a fraction of the cost, with the state enforced on chain |
| G. Zero-knowledge proof of ML-DSA-87 verification (SP1 / RISC Zero) | **no**, as deployed: the proof that lands on Ethereum is Groth16 on BN254, a pairing a quantum computer breaks | a few hundred thousand gas | not built: it would move the quantum weakness, not remove it. A STARK verified directly on L1 is post-quantum but costs several million gas and a verifier contract of its own |
| H. EIP-8051 / EIP-8355 ML-DSA precompiles | yes (EIP-8355 covers levels 2, 3 and 5) | a few thousand gas | drafts: the target once Ethereum ships one; the messenger takes it as one more `IPqAttestationVerifier` |

### Why not ML-DSA-87 on Ethereum today

ML-DSA-87 multiplies a matrix of 8 x 7 polynomials (ML-DSA-44: 4 x 4), with 7 forward and 8 inverse NTTs instead of
4 and 4: about 3.5 times the lattice arithmetic of the 8.3M gas measured above, so roughly 20 to 29M gas, over the
16,777,216 gas a transaction may use. Splitting the check over several transactions would have to store intermediate
polynomials (thousands of words) between them, which costs more than it saves. Two things will change this: ZKNox's
experimental packed verifier (ML-DSA-44 at 1.2M gas, ML-DSA-65 at 1.54M, per their README) extended to level 5, or an
ML-DSA precompile (EIP-8355). Either drops into the messenger as a new verifier through a rotation, and the attester
would then use the very ML-DSA-87 key QoreChain already knows.

## What else changed on Ethereum

- **No owner on the messenger.** The previous Ethereum messenger had an `Ownable` owner, a secp256k1 key that could
  have replaced the attester. The hybrid messenger has none.
- **The secp256k1-only messenger lost its right to mint** (`revokeRole`), on both retired versions.
- **Nonces carry the messenger's address.** Found while migrating (FINDINGS 17): a redeployed messenger counted from
  1 into nonces its predecessor had spent on QoreChain; a return was burned and refused. Fixed in the contract with a
  regression test, and repaired on the testnet without loss (`keeper/src/repair-nonce.ts`).

## What is still classical on Ethereum

The ABF issuer (the partner's contract, simulated here) and the receiver's operator role. The operator can only send
the receiver's money home, to the one allocator fixed at deployment; it cannot redirect it.

## Switching

```bash
cd keeper
npx tsx src/rotate-eth-pq.ts wots      # secp256k1 + Merkle WOTS+
npx tsx src/rotate-eth-pq.ts mldsa44   # secp256k1 + ML-DSA-44
```

Each rotation is itself a hybrid attestation by the keys in place.
